# TheHybit Coins 2.0.x — design v2

## Turning it on

- **Preview, one visit:** add `?thb_design=v2` to any coin page, e.g. `/coin/ethereum/?thb_design=v2`.
  Those URLs are `noindex, follow` (core robots, Yoast and Rank Math), and the canonical never carries the parameter.
- **For everyone:** Settings → TheHybit Coins → «طراحی صفحه ارز» → «جدید (نسخه ۲)». The default is classic.
- `?thb_design=classic` still shows the classic page after v2 becomes the default.
- **Trade button:** same settings screen, «نشانی دکمه معامله». It accepts `{symbol}` and `{slug}` (https only). If you leave it empty, the button is hidden.

The classic templates, CSS and JS are unchanged. The test suite compares the rendered classic page byte for byte with the pre-v2 snapshot, and pins 31 classic files by hash.

## Editorial content (admin-editable)

The new ACF tab «طراحی جدید (v2)» on each coin holds:

| Field | Format, one entry per line |
|---|---|
| شعار کوتاه | one line |
| داستان | `YYYY[-MM-DD] \| title \| text` (only entries with a full date get a pin on the price chart) |
| یادگیری در ۶۰ ثانیه | `title \| text` (up to 5) |
| این کوین برای کیست | `audience \| fit \| text` (labelled on the page as editorial opinion) |
| پرسش‌های متداول | `question \| answer` |

Ethereum and Bitcoin have seed content in `config/coins.php`. The seeder only fills **empty** fields. To fill them on a site that is already set up:

1. Add `define('THB_COINS_SETUP', true);` to wp-config.
2. Run the setup page once.
3. Remove the line.

## New datasets

All three are cache-only. The scheduler fills them, and a page render never fetches them.

| Dataset | Provider / endpoint | Key | Scope | TTL | Requests/hour (2 coins / 100 coins) |
|---|---|---|---|---|---|
| peers | CoinGecko `/coins/markets?ids=…` (list in `config/providers.php → peers`) | none | site | 30 min | 2 / 2 |
| protocols | DefiLlama `/overview/fees/{chain}` + `/v2/historicalChainTvl/{chain}` | none | chain | 1 h | 2 per chain (ETH only today) |
| longchart | DefiLlama prices `coins.llama.fi/chart/coingecko:{id}` (fortnightly); fallback Kraken `/0/public/OHLC` weekly candles | none | coin | 24 h | 0.08 / 4.2 |

All three have Provider Probe entries. Their response shapes are written against the documentation and are **not yet confirmed from the server**.

## Request cost

The cost of a v2 page render is the same as a classic one: Ethereum 7 requests cold and 0 warm. The test suite asserts this.

## Still no source

- **Exchange balances and flows,** only if CoinMetrics' free tier does not include them. They are sold by CryptoQuant, Glassnode and CoinMetrics Pro; none has a free API tier for them.
- **Validator count,** if beaconcha.in refuses this server. Rated.network and others need a paid or application-only key.
- **Radar axes "TVL growth (30d)" and "network activity growth (30d)".**
  - These are components of the classic score.
  - TVL growth fills from the plugin's own history after 30 days.
  - Activity growth reads the `onchain` provider, which is still disabled.
  - Feeding them from a new source would change Ethereum's score, so I left them unchanged.

### Why fields stayed empty on the live site

The scheduler did call CoinMetrics, Lido and DefiLlama prices; the requests failed on the server, and the old code dropped the reason. 2.0.3 records the last error per dataset (`thb_coins_last_errors`, keys scrubbed) and shows it on the diagnostics screen under «آخرین خطای هر داده». After deploying, wait ~15 minutes and read that table.

### Provider refusals (2.0.4)

- **The provider's own words.** Every non-2xx answer is stored with the first ~200 characters of its body, as plain text: HTML refusal pages (Cloudflare and similar) are reduced to their text, and any configured key is scrubbed. A 403 now says *why*, for example "invalid key", "country blocked" or "IP blacklisted".
- **Blockchair bans are not prolonged.** 430 and 434 ("IP temporarily blacklisted") and 402 ("daily limit spent") pause Blockchair for an hour (`block_statuses` / `block_cooldown` in `config/providers.php`), instead of the 5-minute 429 cooldown that kept calling into the ban.
- **The reason survives the pause.** While a provider is paused, each skipped attempt is noted as "now: cooling down … after a 430" beside the original error, instead of replacing it.

### Checked, no free source

- **Active addresses (if CoinMetrics refuses the server):** Etherscan's daily active-address chart is API Pro only; Blockchair `/stats` has no active-address field and its aggregation can't count distinct addresses; Dune needs a key and a saved query; growthepie and Blockscout have no documented stable endpoint for it. An "estimate from transaction count" was **not** built — you asked for no invented numbers.
- **Validators without beaconcha.in:** a public beacon node returns the full validator list (~1M entries, hundreds of MB) — not feasible per tick. Rated.network needs an application key.
- **Coin age / HODL waves beyond `SplyAct1yr`:** Glassnode, CryptoQuant and IntoTheBlock are paid. Santiment's free tier has age data but needs a key and lags 30 days — possible later if you want it.

## DNA radar

The radar plots the five components of the existing Scoring model, with their own weights. The centre shows the same score as the classic page. The reference's six axes are not what the score is made of, so they are not drawn.

## Layout

- **Full width:** the v2 page breaks out of the theme's content box to the full window width. It uses the exact width without the scrollbar, so there is no sideways scroll, and it corrects for off-centre boxes such as sidebar layouts.
- **Width-based breakpoints:** every breakpoint is a container query on the page's own width, not the window's.
  - Desktop (≥1120px): multi-column grids.
  - Tablet (768–1119px): two columns.
  - Phone (<600px): one stacked column.
- **Content width cap:** 1760px. It only matters on very wide monitors; at 1440px the content is 1440 − 2×24px.
- **Tests:** the browser suite renders the page inside three theme layouts (a narrow box, a sidebar layout, and a shrink-to-fit wrapper) at 1440px and 390px. It asserts full width, no overflow, and the column count of each screen.
