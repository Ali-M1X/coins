# TheHybit Coins 2.2.0 — design v2

## Turning it on

- **Preview, one visit:** add `?thb_design=v2` to any coin page, e.g. `/coin/ethereum/?thb_design=v2`.
  Those URLs are `noindex, follow` (core robots, Yoast and Rank Math), and the canonical never carries the parameter.
- **For everyone:** Settings → TheHybit Coins → «طراحی صفحه ارز» → «جدید (نسخه ۲)». The default is classic.
- `?thb_design=classic` still shows the classic page after v2 becomes the default.
- **Trade button:** same settings screen, «نشانی دکمه معامله». It accepts `{symbol}` and `{slug}` (https only). If you leave it empty, the button is hidden.

The classic templates, CSS and JS are unchanged. The test suite compares the rendered classic page byte for byte with the pre-v2 snapshot, and pins 31 classic files by hash.

## Editorial content (admin-editable)

The new ACF tab «طراحی جدید (v2)» on each coin holds:

| Field | Format, one entry per line |
|---|---|
| شعار کوتاه | one line |
| داستان | `YYYY[-MM-DD] \| title \| text` (only entries with a full date get a pin on the price chart) |
| یادگیری در ۶۰ ثانیه | `title \| text` (up to 5) |
| این کوین برای کیست | `audience \| fit \| text` (labelled on the page as editorial opinion) |
| پرسش‌های متداول | `question \| answer` |

Ethereum and Bitcoin have seed content in `config/coins.php`. The seeder only fills **empty** fields. To fill them on a site that is already set up:

1. Add `define('THB_COINS_SETUP', true);` to wp-config.
2. Run the setup page once.
3. Remove the line.

## New datasets

All three are cache-only. The scheduler fills them, and a page render never fetches them.

| Dataset | Provider / endpoint | Key | Scope | TTL | Requests/hour (2 coins / 100 coins) |
|---|---|---|---|---|---|
| peers | CoinGecko `/coins/markets?ids=…` (list in `config/providers.php → peers`) | none | site | 30 min | 2 / 2 |
| protocols | DefiLlama `/overview/fees/{chain}` + `/v2/historicalChainTvl/{chain}` | none | chain | 1 h | 2 per chain (ETH only today) |
| longchart | DefiLlama prices `coins.llama.fi/chart/coingecko:{id}` (fortnightly); fallback Kraken `/0/public/OHLC` weekly candles | none | coin | 24 h | 0.08 / 4.2 |

All three have Provider Probe entries. Their response shapes are written against the documentation and are **not yet confirmed from the server**.

## Request cost

The cost of a v2 page render is the same as a classic one: Ethereum 7 requests cold and 0 warm. The test suite asserts this.

## Still no source

- **Exchange balances and flows,** only if CoinMetrics' free tier does not include them. They are sold by CryptoQuant, Glassnode and CoinMetrics Pro; none has a free API tier for them.
- **Validator count,** if beaconcha.in refuses this server. Rated.network and others need a paid or application-only key.
- **Radar axes "TVL growth (30d)" and "network activity growth (30d)".**
  - These are components of the classic score.
  - TVL growth fills from the plugin's own history after 30 days.
  - Activity growth reads the `onchain` provider, which is still disabled.
  - Feeding them from a new source would change Ethereum's score, so I left them unchanged.

### Why fields stayed empty on the live site

The scheduler did call CoinMetrics, Lido and DefiLlama prices; the requests failed on the server, and the old code dropped the reason. 2.0.3 records the last error per dataset (`thb_coins_last_errors`, keys scrubbed) and shows it on the diagnostics screen under «آخرین خطای هر داده». After deploying, wait ~15 minutes and read that table.

### Provider refusals (2.0.4)

- **The provider's own words.** Every non-2xx answer is stored with the first ~200 characters of its body, as plain text: HTML refusal pages (Cloudflare and similar) are reduced to their text, and any configured key is scrubbed. A 403 now says *why*, for example "invalid key", "country blocked" or "IP blacklisted".
- **Blockchair bans are not prolonged.** 430 and 434 ("IP temporarily blacklisted") and 402 ("daily limit spent") pause Blockchair for an hour (`block_statuses` / `block_cooldown` in `config/providers.php`), instead of the 5-minute 429 cooldown that kept calling into the ban.
- **The reason survives the pause.** While a provider is paused, each skipped attempt is noted as "now: cooling down … after a 430" beside the original error, instead of replacing it.

### Checked, no free source

- **Active addresses (if CoinMetrics refuses the server):** Etherscan's daily active-address chart is API Pro only; Blockchair `/stats` has no active-address field and its aggregation can't count distinct addresses; Dune needs a key and a saved query; growthepie and Blockscout have no documented stable endpoint for it. An "estimate from transaction count" was **not** built — you asked for no invented numbers.
- **Validators without beaconcha.in:** a public beacon node returns the full validator list (~1M entries, hundreds of MB) — not feasible per tick. Rated.network needs an application key.
- **Coin age / HODL waves beyond `SplyAct1yr`:** Glassnode, CryptoQuant and IntoTheBlock are paid. Santiment's free tier has age data but needs a key and lags 30 days — possible later if you want it.

## Launch build (2.0.5)

### Providers: what changed

CoinMetrics and Lido refuse the production server **by location**: Cloudflare 1009 ("the site owner has banned the visitor's country") for CoinMetrics, and "Access to our services from your current location is unavailable" for Lido. No key or paid plan changes that, and the plugin does not route around it. Both are switched off in `config/providers.php` (`'enabled' => false`), with the reason written beside them.

| Figure | Before | Now | Request cost |
|---|---|---|---|
| Daily active addresses (Ethereum) | CoinMetrics `AdrActCnt` | **growthepie** `api.growthepie.com/v1/fundamentals.json`, rows `metric_key = daa`, `origin_key = ethereum` (keyless) | dataset `activity`, chain scope, TTL 6 h → about 4 a day; budget 1/min, 6/h, 24/day |
| Staking APR fallback (when beaconcha.in has none) | Lido `/protocol/steth/apr/sma` | **DefiLlama Yields** `yields.llama.fi/chart/747c1d2a-c668-4682-b9f9-296708a3dd90` (DefiLlama's "stETH — Lido" pool), 7-day mean of the daily APY, labelled «DefiLlama (stETH لیدو)» | dataset `stakingyield`, chain scope, TTL 6 h → about 4 a day; budget 2/min, 10/h, 60/day |
| Net supply inflation → real yield | CoinMetrics `SplyCur` | **Our own Etherscan readings.** History now keeps the `supply` dataset's `totalSupply` every 6 hours; inflation is the annualised change between readings at least 6 days apart | no new requests (it reuses the existing Etherscan supply call) |
| Long-term holders (coin age) | CoinMetrics `SplyAct1yr` | **Removed from the page.** No free source this server can reach | — |
| Exchange in/out flows | CoinMetrics `FlowIn/OutExNtv` | **Not drawn** (they were only in the daily-pulse sentences) | — |
| Supply on exchanges | CoinMetrics, else Etherscan labelled wallets | Etherscan labelled wallets, labelled «(حداقل)» | unchanged |
| Bitcoin active addresses | CoinMetrics | **Not drawn**: growthepie covers Ethereum only | — |

- **Cost:** page-render cost is unchanged (Ethereum 7 cold / 0 warm). Both new datasets are fetched by the scheduler only.
- **Probe entries:** both new sources have Provider Probe entries ("v2 activity", "v2 stakingyield"), and the CoinMetrics and Lido entries are marked OFF.
- **If a replacement is refused too:** its rows are left out entirely instead of showing "unavailable". While a source has never been asked, its row says "در حال دریافت داده". Once it has failed (an entry appears in «آخرین خطای هر داده»), the row is not drawn. The diagnostics table still shows why.
- **Real yield in the first week:** the card shows the staking APR alone, with the sentence "real yield is calculated once two supply readings at least 6 days apart are recorded". It then fills in by itself.
- **Not tested from the production server:** this build environment cannot reach growthepie or DefiLlama. Both response formats follow the providers' documentation. The DefiLlama pool id was confirmed on defillama.com/yields/pool/747c1d2a-c668-4682-b9f9-296708a3dd90. The first scheduler run on the live site is the real test: the Provider Probe entries and the error table show its outcome.

### Timeline joins

Lines of the story timeline wrap at the container's edge. `v2.js` now joins the end of each line's rail to the start of the next with one continuous curve, drawn in the rail's colour: down the right margin, back along the gap, and down into the first event. The join is dashed violet when the next line starts with a planned event.

- Where the lines break depends on the width, so the joins are measured on load and redrawn on resize.
- On a phone (one event per line) no joins are drawn.
- Without JavaScript the events read the same, just unjoined.
- The browser suite checks that each join starts exactly at a rail's end and ends at the next rail's start, at 1440 and 900 px.

## 2.2.0 — coin list at /coins/, two coin-page fixes

### Launch date: Gregorian only

The About card's launch date used ICU with `fa_IR` and the calendar overridden to Gregorian. On hosts whose ICU takes the month names from the locale's default (Persian) calendar, that prints a Gregorian day and year around a Jalali month.

- **New formatter:** v2 now uses `Format::gregorian()`, built from a fixed table of Gregorian month names, e.g. «30 ژوئیه 2015».
- **Markup:** the date is wrapped as `<time datetime="2015-07-30">`.
- **Classic page:** keeps `gregorianFa()` and stays byte-identical to 1.8.0.

### Data-sources list: admin only

The «منابع داده و زمان آخرین به‌روزرسانی» list is no longer in the public page's markup or its data island. It is now a table on the diagnostics screen (Settings → TheHybit Coins → diagnostics), for the coin selected there: what each figure is, its source, and when it was fetched (Tehran time and UTC).

### The coin list (`/coins/`, `/coins/page/2/` …)

- **Routing:** the coin post type's archive, rendered by `templates/v2/archive-coins.php`. A theme can override it at `thehybit/v2/archive-coins.php`.
- **Rewrite rules:** the archive and its pagination rules already exist (`has_archive => 'coins'`), so nothing needs flushing.
- **If `/coins/` doesn't show the list:** a WordPress Page with the slug `coins` would compete with the archive. Rename that Page's slug.
- **Data:** CoinGecko `/coins/markets`, ordered by market cap, 100 coins per request, in `includes/Listing.php`. The scheduler refreshes at most one page per tick, after the live price, through the CoinGecko budget:

  | | Refresh | Requests/hour |
  |---|---|---|
  | Page 1 (coins 1–100) | every 5 min | 12 |
  | Pages 2–5 (coins 101–500) | every 30 min | 8 |
  | **Total** | | **20 (~480/day)** |

  The rest of the plugin uses about 100/hour of our 200/hour CoinGecko budget, so the total stays around 125/hour. Each extra page costs 2/hour (`listing.pages` in `config/providers.php`).
- **No per-coin requests.** Logos are CoinGecko's image URLs from the same response, loaded lazily by the browser, as the coin page already does for coins without a featured image. Coins with a page on the site use its featured image when there is one.
- **Page renders read the cache only.** A list page the scheduler has not filled yet says «در حال دریافت داده»; it never shows zeros.
- **Columns:** #, coin (logo, name, symbol), price, 24h, 7d, **vs market**, market cap, 24h volume, 7-day sparkline.
  - Coins with a page on the site link to it under their Persian name, marked with a dot.
  - Phone shows #, coin, price (24h under it) and vs market.
  - Tablet adds 24h, 7d and market cap; desktop shows all columns.
  - Columns respond to the container's width; the table never scrolls sideways (tested at 1440, 900 and 390px).
- **The distinctive column, «در برابر بازار»:** the coin's 7-day change minus the market's 7-day change. "The market" is the top 100 weighted by market cap, also shown at the top of the page.
  - It answers "did this coin beat the market this week, and by how much", regardless of whether the market went up or down.
  - It is computed from page 1 of the same response: no request of its own.
  - A coin with no 7-day figure gets "—", never a zero.
- **Pagination:** 100 coins per page, with real `/coins/page/N/` links (`rel="prev"` / `rel="next"`), so nothing is loaded that isn't shown and every page is crawlable. The list covers the top 500 (5 pages); page 6 and beyond return 404.
- **SEO:**
  - Server-rendered, with one h1 and section h2s, and a real `<table>` with a caption and column and row headers.
  - Each page has its own title and meta description, through the Yoast filters plus `document_title_parts` without Yoast. Page 2 onward carries the page number.
  - Breadcrumb: خانه › ارزها.
- **Lighthouse (local build, test data):**

  | | Performance | Accessibility | Best practices | SEO |
  |---|---|---|---|---|
  | Mobile, gzip-compressed | 100 (LCP 1.5 s, TBT 0 ms) | 100 | 96 | 100 |
  | Mobile, uncompressed | 81 | | | |
  | Desktop | 100 | 100 | 96 | 100 |

  - The page is about 283KB of HTML before compression and about 40KB gzipped, so make sure the server compresses HTML; most hosts do by default.
  - Best practices is 96 only because of the local favicon 404.

## Launch (2.1.0)

2.1.0 is the 2.0.5 launch build plus one fix that Lighthouse found: a primary button that is a link (the trade button) inherited light text on its teal fill, a 1.41:1 contrast. It now keeps its dark text.

- **Rollback point:** v1.8.0, unchanged. Tag `v1.8.0` and branch `v1.8.0` both point to `c09a563`, which is the shipped zip extracted unchanged.
- **Release tag:** `v2.1.0`.

### Going live, in order

1. **Upload** `thehybit-coins-2.1.0.zip` over the installed plugin (Plugins → Add New → Upload; replace the current version). The design setting is not touched, so visitors keep seeing whatever is set now.
2. **Check on production data** before switching: open `https://thehybit.com/coins/ethereum/?thb_design=v2` on desktop and on a phone.
   - Every figure is real or has no row.
   - There is no long-term-holder row and no exchange-flow sentence. Those are not hidden with CSS; the server never writes them.
   - The timeline wraps with joined lines.
   - Then open Settings → TheHybit Coins → diagnostics: run the Provider Probe entries "v2 activity" and "v2 stakingyield", and read «آخرین خطای هر داده».
3. **Switch:** Settings → TheHybit Coins → «طراحی صفحه کوین» → «جدید (نسخه ۲)» → Save. Or with WP-CLI:
   `wp option patch update thb_coins_settings design v2`
   (use `patch insert` instead of `patch update` if the settings have never been saved).
4. **Purge the page cache / CDN** if the site has one, then open `https://thehybit.com/coins/ethereum/` with no parameter.
   - Is it the new design? View the page source and search for `thb-v2-host`; the classic page does not contain it.
   - The page must have **no** `noindex`: only `?thb_design=` URLs are noindex, and the plain URL keeps its normal robots and canonical.

### Rollback

- **One line:** Settings → TheHybit Coins → «طراحی صفحه کوین» → «کلاسیک (نسخه ۱.۸)» → Save, then purge the cache. Or with WP-CLI:
  `wp option patch update thb_coins_settings design classic`
- **Effect:** the classic page renders byte-identical to v1.8.0 (the suite checks this), and `?thb_design=v2` keeps working for comparison.
- **Full code rollback:** install the v1.8.0 zip (tag `v1.8.0`).

## DNA radar

The radar plots the five components of the existing Scoring model, with their own weights. The centre shows the same score as the classic page. The reference's six axes are not what the score is made of, so they are not drawn.

## Layout

- **Full width:** the v2 page breaks out of the theme's content box to the full window width. It uses the exact width without the scrollbar, so there is no sideways scroll, and it corrects for off-centre boxes such as sidebar layouts.
- **Width-based breakpoints:** every breakpoint is a container query on the page's own width, not the window's.
  - Desktop (≥1120px): multi-column grids.
  - Tablet (768–1119px): two columns.
  - Phone (<600px): one stacked column.
- **Content width cap:** 1760px. It only matters on very wide monitors; at 1440px the content is 1440 − 2×24px.
- **Tests:** the browser suite renders the page inside three theme layouts (a narrow box, a sidebar layout, and a shrink-to-fit wrapper) at 1440px and 390px. It asserts full width, no overflow, and the column count of each screen.
