# TheHybit Coins 2.10.0 — design v2

## Turning it on

- **Preview, one visit:** add `?thb_design=v2` to any coin page, e.g. `/coin/ethereum/?thb_design=v2`.
  Those URLs are `noindex, follow` (core robots, Yoast and Rank Math), and the canonical never carries the parameter.
- **For everyone:** Settings → TheHybit Coins → «طراحی صفحه ارز» → «جدید (نسخه ۲)». The default is classic.
- `?thb_design=classic` still shows the classic page after v2 becomes the default.
- **Trade button:** same settings screen, «نشانی دکمه معامله». It accepts `{symbol}` and `{slug}` (https only). If you leave it empty, the button is hidden.

The classic templates, CSS and JS are unchanged. The test suite compares the rendered classic page byte for byte with the pre-v2 snapshot, and pins 31 classic files by hash.

## Editorial content (admin-editable)

The new ACF tab «طراحی جدید (v2)» on each coin holds:

| Field | Format, one entry per line |
|---|---|
| شعار کوتاه | one line |
| داستان | `YYYY[-MM-DD] \| title \| text` (only entries with a full date get a pin on the price chart) |
| یادگیری در ۶۰ ثانیه | `title \| text` (up to 5) |
| این کوین برای کیست | `audience \| fit \| text` (labelled on the page as editorial opinion) |
| پرسش‌های متداول | `question \| answer` |

Ethereum and Bitcoin have seed content in `config/coins.php`. The seeder only fills **empty** fields. To fill them on a site that is already set up:

1. Add `define('THB_COINS_SETUP', true);` to wp-config.
2. Run the setup page once.
3. Remove the line.

### Why fields stayed empty on the live site

The scheduler did call CoinMetrics, Lido and DefiLlama prices; the requests failed on the server, and the old code dropped the reason. 2.0.3 records the last error per dataset (`thb_coins_last_errors`, keys scrubbed) and shows it on the diagnostics screen under «آخرین خطای هر داده». After deploying, wait ~15 minutes and read that table.

### Provider refusals (2.0.4)

- **The provider's own words.** Every non-2xx answer is stored with the first ~200 characters of its body, as plain text: HTML refusal pages (Cloudflare and similar) are reduced to their text, and any configured key is scrubbed. A 403 now says *why*, for example "invalid key", "country blocked" or "IP blacklisted".
- **Blockchair bans are not prolonged.** 430 and 434 ("IP temporarily blacklisted") and 402 ("daily limit spent") pause Blockchair for an hour (`block_statuses` / `block_cooldown` in `config/providers.php`), instead of the 5-minute 429 cooldown that kept calling into the ban.
- **The reason survives the pause.** While a provider is paused, each skipped attempt is noted as "now: cooling down … after a 430" beside the original error, instead of replacing it.

### Checked, no free source

- **Active addresses (if CoinMetrics refuses the server):** Etherscan's daily active-address chart is API Pro only; Blockchair `/stats` has no active-address field and its aggregation can't count distinct addresses; Dune needs a key and a saved query; growthepie and Blockscout have no documented stable endpoint for it. An "estimate from transaction count" was **not** built — you asked for no invented numbers.
- **Validators without beaconcha.in:** a public beacon node returns the full validator list (~1M entries, hundreds of MB) — not feasible per tick. Rated.network needs an application key.
- **Coin age / HODL waves beyond `SplyAct1yr`:** Glassnode, CryptoQuant and IntoTheBlock are paid. Santiment's free tier has age data but needs a key and lags 30 days — possible later if you want it.

- **Cost:** page-render cost is unchanged (Ethereum 7 cold / 0 warm). Both new datasets are fetched by the scheduler only.
- **Probe entries:** both new sources have Provider Probe entries ("v2 activity", "v2 stakingyield"), and the CoinMetrics and Lido entries are marked OFF.
- **If a replacement is refused too:** its rows are left out entirely instead of showing "unavailable". While a source has never been asked, its row says "در حال دریافت داده". Once it has failed (an entry appears in «آخرین خطای هر داده»), the row is not drawn. The diagnostics table still shows why.

### Timeline joins

Lines of the story timeline wrap at the container's edge. `v2.js` now joins the end of each line's rail to the start of the next with one continuous curve, drawn in the rail's colour: down the right margin, back along the gap, and down into the first event. The join is dashed violet when the next line starts with a planned event.

- Where the lines break depends on the width, so the joins are measured on load and redrawn on resize.
- On a phone (one event per line) no joins are drawn.
- Without JavaScript the events read the same, just unjoined.
- The browser suite checks that each join starts exactly at a rail's end and ends at the next rail's start, at 1440 and 900 px.

## 2.10.0 — price converter

- **Where.** On every coin page, as a «مبدل» tab and section right after the overview. Also standalone at `/coins/convert/`, which starts at Bitcoin → USD and adds a table of one unit of every coin in USD and toman.
- **Units.** Coin ↔ USD, coin ↔ toman, coin ↔ any of our coins.
- **Rates — all already cached, each printed with its time:**
  - The site-wide live-price entry, refreshed every minute; one read covers every coin.
  - The coin's 5-minute market entry, before the first refresh.
  - The USD→toman rate from PersianToolbox, refreshed every 15 minutes. With no such rate there is **no toman option at all** and the block says so; no rate is ever assumed.
- **Live ticks.** On a coin page, this coin follows the 2.4.0 live feed:
  - Kraken in USD, and Nobitex's toman market for coin↔toman.
  - `live.js` now announces each repaint as a `thb:live` event, and the converter listens to that event.
  - The meta line says when a figure is live.
- **Input and output.**
  - **Input:** Persian, Arabic or Latin digits, «٫» or «.», and thousands separators. Anything else is refused with a message and `aria-invalid`.
  - **Output:** Persian digits with «٬» and «٫».
  - **Rounding:** cents for dollars, whole tomans, and up to 8 decimals for small coin amounts.
- **No requests.** Conversion happens in the browser, with no request per conversion.
- **Without script.** The block is a GET form to `/coins/convert/`, and the server computes the same answer.
- **SEO.**
  - Each coin's block has its own short text, built from that coin's name, category, price and which of its rates are live; all 84 differ.
  - `/coins/convert/` is one indexable page with its own title, description and canonical.
  - Any `?from=&to=&amount=` state is `noindex, follow` with the canonical on the bare page.
  - The new route is flushed once per version on the first wp-admin visit.
- **Request cost.** Zero external requests. Ethereum stays at 7 requests cold / 0 warm.

## 2.9.0 — search in the coin list

- **What is searched.** Every coin the list knows, not just the 100 on screen: all cached list pages (up to 500 coins), plus any coin with a page here that ranks lower. It matches the Persian name, the English name and the symbol.
- **What is forgiven.** Arabic ي/ك, alef and hamza forms, diacritics, a space or no space instead of the half-space, Persian and Arabic digits, and case. A symbol typed on the Persian keyboard by mistake («ذفز») is read again as «btc», and the page says so.
- **With script.** Results appear as you type. The index (about 64 KB, roughly 12 KB compressed) is fetched once per visit, on first focus, from `GET /wp-json/thehybit/v1/coins-index`. That endpoint:
  - is built from the cache only (never a provider);
  - is rebuilt at most once a minute;
  - is browser-cacheable for 5 minutes;
  - is rate-limited to 30 requests a minute per visitor (HTTP 429 with Retry-After), keyed on a salted hash of the connection's address, with no address stored.

  There is no request per keystroke, and Escape clears the search.
- **Without script.** The same form submits `/coins/?q=`, and the server renders the results.
- **Filters.** Search works inside a category (`?q=…&cat=…`) and replaces the pagination while active.
- **Sharing and indexing.** The address keeps `?q=`, so a search can be shared. Search views are `noindex, follow`.
- **Request cost.** Zero external requests. Page renders are unchanged (Ethereum 7 cold / 0 warm).

## 2.4.0 — live price over the visitor's WebSocket

Price and 24h change on the v2 coin pages and on `/coins/` now update tick by
tick. **The visitor's browser** connects directly to the exchanges' public
WebSocket feeds (`assets/v2/live.js`, about 400 lines, no dependencies). The
server never opens, relays or proxies a socket. A page render makes no extra
request: Ethereum is still 7 cold / 0 warm. Everything else (TVL, sentiment,
network, score, chart history, **volume**) keeps the server refresh.

**Turning it off:** Settings → TheHybit Coins → «قیمت زنده (WebSocket)» → خاموش.
That removes the script and its JSON from every page; the pages are exactly as
in 2.3.0, one-a-minute polling included. Per feed: `config/providers.php` →

### Behaviour

- **No invented numbers.** The server-rendered figure stays until a real tick
  arrives. A coin no feed lists is never touched.
- **One socket per exchange per page**, never one per coin. At most two, and
  one when only one exchange carries the page's coins.
- **Repaints** happen at most once a second per coin. A rise flashes green and
  a fall red; with `prefers-reduced-motion` there is no flash. The price box
  only grows (reserved width, tabular digits), so the line never shifts.
- **Stale, not frozen.** If a feed is silent for 15 s (Kraken) or 40 s
  (Nobitex), or its socket drops:
  - the figure dims;
  - its tooltip and the stamp say «اتصال زنده قطع شد · آخرین قیمت زنده HH:MM:SS»;
  - the page's polling takes the figure back as soon as it has a newer value.
- **Arbitration.** A poll never overwrites a live figure while its feed is
  fresh. Once the feed is gone, a poll replaces it only if it was fetched after
  the last live tick.
- **Reconnect** uses jittered exponential backoff (1 s, 2 s, 4 s … up to 60 s).
  A feed that never delivered a message gives up after 5 tries (a blocked
  region): the page is then exactly the polling page, with no error shown.
- **Hidden tab:** the sockets close after 10 s hidden and reopen on return. A
  value pushed before the pause is not shown as live after it.
- **SEO** is unchanged: the price is in the first response, and the structured
  data is still written by the server only.

### Limits and terms (check before relying on it)

- **Kraken:** public, no key. About 150 connection attempts per 10 minutes per
  IP (Cloudflare). Kraken blocks sanctioned jurisdictions, Iran included, so
  most Iranian visitors will not reach it and will get the Nobitex fallback or
  polling. No published API-data licence was found; Kraken licenses data
  commercially through resellers. **Get written confirmation before relying on
  it on an ad-supported site.**
- **Nobitex:** officially documented, no token for `public:` channels. 100
  connections per IP, 450 channels per connection; the server pings `{}` and
  expects `{}` within 25 s. Its terms page (apidocs.nobitex.ir/terms) could not
  be read from the build environment, so **check it**. Showing a competing
  exchange's prices next to your own «معامله» button is also a business
  decision. To use Kraken only, set
  `live_ws.feeds.nobitex.enabled => false`.
- **CSP:** a site with a Content-Security-Policy must allow
  `connect-src wss://ws.kraken.com wss://ws.nobitex.ir`. Without that, the
  browser refuses the socket and the page silently stays on polling.

2. **A fairer ticker reservation.** The live ticker's reserved slot was counted twice: its own calls counted against everything else's allowance as well. ## Layout

- **Full width:** the v2 page breaks out of the theme's content box to the full window width. It uses the exact width without the scrollbar, so there is no sideways scroll, and it corrects for off-centre boxes such as sidebar layouts.
- **Width-based breakpoints:** every breakpoint is a container query on the page's own width, not the window's.
  - Desktop (≥1120px): multi-column grids.
  - Tablet (768–1119px): two columns.
